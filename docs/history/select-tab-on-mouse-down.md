# タブを掴んだ時点でアクティブにする

## Issue

- #268

## 目的

バックグラウンドのタブをドラッグするときも、掴んだタブを即座にアクティブにする。
通常のクリックも同じタイミングで選択し、Chromeのように押した時点で内容を表示する。

## 調査結果

- `TerminalTabItemView.mouseDown(with:)`は押下イベントを記録し、ダブルクリック時に名前編集を開始する。
- タブ選択は`mouseUp(with:)`だけで行っている。
- `mouseDragged(with:)`は移動量が4ポイントを超えると押下イベントをクリアしてドラッグを開始するため、選択処理を通らない。
- 既存の`onSelect`は`BaseTerminalController.selectTab(_:)`につながり、タブ切り替えと端末へのフォーカス移動を処理する。同じタブの再選択は無視する。
- 並び替え処理は選択状態を維持する。ここで選択を変えるとドラッグ開始時やキャンセル時の要望を満たせない。

## 実装方針

- `mouseDown(with:)`で押下イベントを記録した後、既存の`onSelect`を呼ぶ。
- ダブルクリック時の名前編集は、選択の後に行う。
- `mouseUp(with:)`から選択処理を取り除き、押下イベントの後始末だけを行う。
- ドラッグの閾値、ドラッグセッション、並び替え、右クリックメニュー、閉じるボタンの処理は変更しない。
- ドラッグ開始時だけ選択する案も考えられるが、押下時の選択に統一することで通常クリックとドラッグの動作を揃える。

## 検証

- `TerminalTabTests`にマウス押下イベントを使う回帰テストを追加し、マウスを離す前に対象タブが選択されることと、ダブルクリック時に選択後に名前編集されることを確認する。
- 既存の並び替えとバックグラウンドタブのコンテキストメニューテストを実行する。
- Swiftのlintと、変更に関連するmacOSテスト・ビルドを実行する。
- 実機では、非選択タブの押下・ドラッグ中・並び替え後・ドラッグキャンセル後の選択状態と端末の入力フォーカスを確認する。
- 名前編集、閉じるボタン、右クリックで意図せずタブが切り替わらないことも確認する。

## 実装結果

- `mouseDown(with:)`で選択し、`mouseUp(with:)`では押下イベントだけをクリアするよう変更した。
- 通常クリックとダブルクリックをパラメータ化した回帰テストを追加した。マウスを離す前の選択、名前編集より先の選択、マウスを離した時の選択処理の重複がないことを確認する。
- ユーザーの指示により、プランだけのdraft PRを挟まず実装を含む通常のPRにまとめた。
