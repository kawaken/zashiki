# Markdownプレビューを外部アプリで開く

## Issue

- #267

## 目的とUI

- 現在プレビューしているファイルを、登録した外部アプリで開けるようにする。
- ヘッダーの外部アプリ起動ボタンは、通常クリックで設定したデフォルトアプリを開く。
- ファイル名メニューに`Open With`とアプリ一覧を追加する。デフォルトにはチェックを付ける。
- 同じメニューの`Configure External Apps…`とアプリメニューから専用の設定ウィンドウを開く。
- 設定にはアプリ一覧、追加・編集・削除、デフォルト選択を用意する。
- 既存のPreferencesによる設定ファイル編集は維持し、今回のために一般設定画面全体を作り直さない。
- 標準候補はObsidianとVisual Studio Codeとする。ユーザーの指定により、URLスキームで開けないアプリは対象に含めない。

## 調査結果

- `SettingsView`は案内だけの未使用画面で、現在のPreferencesは`AppDelegate.openConfig`を呼んで設定ファイルを開く。
- ファイル名のメニューは#272 / PR #274で実装済み。#274がマージされた最新の`origin/main`から専用ブランチで作業する。
- Obsidianは`obsidian://open?path=...`に絶対パスを渡せる。ファイルがObsidianのVault内にあることが必要。
- Visual Studio Codeは`vscode://file/{full path}`でファイルを開ける。
- CotEditorの公式Info.plistには独自URLスキームの宣言がないため、今回は標準候補に含めない。

## 設計

- 外部アプリの登録は表示名とURLテンプレートを持つ。
- URLテンプレートの`{path}`をプレビュー中ファイルの絶対パスで置換する。URLのパス部分とクエリ部分ではエンコード規則を分け、空白・日本語・`#`・`?`・`&`・`%`などを正しく扱う。
- URLの登録・編集ではテンプレートの形式を検証し、不完全な登録を保存しない。
- 設定は`UserDefaults.zashiki`へ保存する。追加・編集・削除・デフォルト変更を即時反映し、アプリ再起動後も保持する。
- デフォルトの登録を削除した時は残りの先頭を選び、登録が空なら起動ボタンを無効にする。
- 未選択ファイルの起動は無効にする。アプリ未インストールや起動要求の失敗はプレビューにエラー表示する。
- macOSのURL起動APIを使う。アプリを指定するファイル起動APIやシェルコマンドは実行しない。

## 実装中の確認事項

- URLをパースする際、`vscode://file{path}`のプレースホルダーを単なる文字列へ置換するとホスト名の一部として解釈される。絶対パスと同じ先頭スラッシュ付きの仮値でパースし、パス・クエリの各部分で正しく置換する。

## 検証

- URL生成: パス・クエリの違い、日本語、空白、URL予約文字、不正なテンプレート。
- 設定保存: 登録編集、削除時のデフォルト、空の一覧、再読み込み、標準候補。
- lint、関連するSwiftテスト、アプリのCIビルド。
- 実機でObsidianとVisual Studio Codeへの起動、デフォルト選択、設定の永続化、未インストール時、狭いパネルの表示を確認する。
- 通常PRに`needs-verification`を付け、アプリ成果物で確認できるようにする。確認完了までAutoMergeは有効にしない。

## 実装結果

- URLスキームでの起動に限定し、標準候補はObsidianとVisual Studio Codeとした。登録には表示名と`{path}`を含むURLテンプレートを使う。
- 外部アプリボタンの通常クリックでデフォルトを起動し、右クリックまたはファイル名メニューの`Open With`で他の登録を選択できる。
- 専用ウィンドウに登録一覧・デフォルト選択・追加編集削除を実装した。アプリメニューからも開けるため、ファイル未選択時にも設定できる。
- 登録を削除した場合は残った先頭をデフォルトにし、すべて削除した場合は起動ボタンを無効にする。空の一覧も再起動後に保持する。
- URLハンドラーが登録されていない場合やOSが起動要求を受け付けない場合はエラーを表示する。URLを受け取った外部アプリ側でのファイル表示結果は実機確認の対象とする。

## ローカル検証結果

- `just lint`: 成功（Swift 199ファイル、違反なし）。
- 変更したSwiftの構文チェック、XIBのXML検証、`git diff --check`: 成功。
- モデル・専用設定画面・ファイル監視・応答処理の実ソースを依存なしの一時Swiftパッケージでビルドし、既存のプレビューモデル21テストと外部アプリ設定4テストの計25テストが成功。一時パッケージは提出差分には含めない。
- 先頭スラッシュのない仮値ではVS CodeのURLがホストとして解釈される不具合をテストで検出し、先頭スラッシュ付きの仮値に修正した。日本語・空白・`#`・`?`・`&`・`%`・`+`を含むパスの復元と、クエリへのスラッシュの符号化を確認した。
- 設定の追加編集・デフォルト選択・削除時のフォールバック・空の一覧の再読み込み、不正なテンプレートを保存しないことを確認した。
- ローカルではMetal Toolchainを利用できないため、アプリ全体のビルドはCIで確認する。外部アプリへの実際の起動と設定画面の操作・表示は未確認。
