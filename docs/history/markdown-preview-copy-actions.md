# Markdownプレビューのコピー操作

## Issue

- #272

## 決定したUIと動作

- ヘッダーのファイル名を小さな下向き矢印付きのメニューにする。
- メニューには`Copy Markdown`、`Copy Absolute Path`、`Copy Relative Path`を並べる。
- Markdownはフロントマターを含む原文全体、パスはシェルエスケープなしの文字列としてコピーする。
- Finderで表示する既存ボタンと、履歴・文字サイズ・閉じる操作は残す。
- 相対パスは`zashiki +markdown-preview`を呼び出した時の作業ディレクトリを基準にする。端末のフォーカス、後続の`cd`、tmuxの外側の作業ディレクトリには依存させない。
- 基準ディレクトリは相対パス項目のヘルプに表示する。基準情報がない履歴では相対パスのコピーを無効にする。
- ファイル未選択ではファイル名メニューを無効にする。読み込みエラー時はMarkdownのコピーを無効にし、パスのコピーは利用可能にする。

## 調査結果と実装方針

- プレビューパネルの開閉はウィンドウで共有し、ファイル・履歴・スクロール位置は`TerminalTab.markdownPreview`でタブごとに管理している。
- CLIはファイルパスを`realPathFile`で絶対パスに解決し、`zashiki://markdown-preview/open`へ渡している。呼び出し元の作業ディレクトリも実パスで取得し、任意の`base-directory`クエリとして送る。
- アプリは`base-directory`がある場合に絶対パスであることを検証する。省略された既存URLはそのまま利用できる。
- `MarkdownPreviewHistoryEntry`に任意の基準ディレクトリを追加し、内部履歴もこの項目を保持する。戻る・進む・履歴選択でメタ情報を復元する。
- 相対パスは正規化したパスコンポーネントの共通部分から求める。基準の外にあるファイルには`../`を付け、共通の文字列接頭辞だけで判定しない。
- 同じファイルを異なる基準から開いても、基準をファイル単位で上書きせず、各履歴項目に保持する。
- 合意済みの設計を実装し、プランだけのdraft PRを挟まず通常PRにまとめる。

## 実装中の確認事項

- Zigの`Dir.cwd()`はmacOSでは実ファイル記述子ではなく`AT_FDCWD`を返す。標準ライブラリのソース確認により、そのまま`realPath`へ渡すのではなく、`realPathFile(".")`で呼び出し元の作業ディレクトリを解決する必要があると分かった。
- 呼び出し元ディレクトリを取得できない場合も、絶対パスでのプレビューは従来どおり可能にし、基準情報だけ省略する。
- Metal Toolchain不足により通常のZigテストが実行できない。モデル・ファイル監視・応答処理の実ソースと既存のSwiftテストを、作業用キャッシュ内の依存なしSwiftパッケージでも実行して確認する。これはアプリ全体のビルド・テストの代替とはしない。

## 検証

- CLIのURL生成テストで、基準パスのクエリ符号化と既存のterminal-id・応答パスを確認する。
- Swiftテストで子・兄弟ディレクトリ、日本語・空白、似たディレクトリ名、基準情報なしの相対パスを確認する。
- 同一ファイルを異なる基準から開き、戻る・進む・履歴選択・進む履歴の破棄・再読み込み後もメタ情報が正しいことを確認する。
- 原文全体のコピー、空ファイル、読み込みエラーの扱いを確認する。
- lint、変更に関連するZigテスト、macOSテスト・ビルドを実行する。Metal Toolchain不足が続いている場合は検証範囲を明記する。
- PRには`needs-verification`を付け、CIのアプリ成果物でメニューの表示・コピー・tmuxからの呼び出し・履歴移動を確認できるようにする。確認完了まではAutoMergeを有効にしない。

## 実装結果

- ファイル名を下向き矢印付きのメニューにし、Markdown原文・絶対パス・相対パスをコピーできるようにした。ファイル名のフルパス表示と既存のFinderボタンは維持した。
- CLIの`base-directory`クエリで呼び出し元の実ディレクトリを伝え、アプリ側で任意の絶対パスとして受け取る。従来のクエリ省略時は基準なしとして扱う。
- 内部履歴をURLだけの配列からメタ情報付きの履歴項目へ変更した。基準ディレクトリは開いた時点の値として保持し、再読み込み・タブのフォーカス・ディレクトリ変更で書き換えない。
- 基準の外にあるファイルも`../`付きでコピーできる。空白や日本語をそのまま保持し、シェルエスケープやURL符号化はコピー結果に含めない。
- 原文コピーは空ファイルも扱い、読み込みに失敗した時は古い内容をコピーしない。

## ローカル検証結果

- `just lint`: 成功（Swift 196ファイル、違反なし）。最終変更したSwiftファイルのlintとZigのフォーマット確認も成功。
- 変更したSwiftファイルの構文チェックと`git diff --check`: 成功。
- 一時的なZigテストルートから既存のCLIモジュールを直接読み込み、CLIの6テストが成功。基準ディレクトリの符号化、メタ情報なしのURL生成、引数解析、無効なterminal-idを確認した。CLIアクション検出の既存テストも成功。一時的なテストルートは提出差分には含めない。
- モデル・ファイル監視・応答処理の実ソースと`MarkdownPreviewModelTests`を依存なしの一時Swiftパッケージでビルドし、21テスト成功。相対パスの計算、履歴ごとの基準、原文全体・空ファイル・エラー時のコピー可否、既存の履歴とスクロール位置を確認した。一時パッケージは提出差分には含めない。
- `just test-filter 'markdown preview'`: Metal Toolchain不足によりMetalシェーダーのコンパイルで失敗。ローカルでのアプリ全体のビルド・macOSテストは未完了。
- メニューの実表示、実際のクリップボード、tmux経由でのサブコマンド呼び出しはPRのアプリ成果物で実機確認する。
