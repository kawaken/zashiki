# 左右パネルをウィンドウ直下に置き、タブをその間に入れる

Issue #208

## 目標

「Window → 左右パネル → タブ（タブ内部での分割）」の構造にする。

```
┌───────────────────────────────────────────────┐
│ ●●●               タイトル                     │
├────────┬────────────────────────┬─────────────┤
│ 左     │ tab1 │ tab2 │ tab3 │ + │ 右          │
│ パネル ├────────────────────────┤ プレビュー  │
│        │ ターミナル（ペイン分割） │             │
└────────┴────────────────────────┴─────────────┘
```

- 左右パネルの枠はウィンドウに1つ。タブを切り替えても位置・幅・開閉が変わらない。
- パネルの中身は選択中のタブに連動する。左は選択中のタブのディレクトリ、右の Markdown
  プレビューは選択中のタブで開いたファイルを表示する。
- タブバーは左右パネルの間だけに表示される。

## 現状（コードで確認済み）

- タブは macOS 標準のタブ機能。1タブ = 1 `NSWindow` = 1 `TerminalController` で、
  `NSWindowTabGroup` が見た目上1つのウィンドウにまとめている。
- タブバーは AppKit がタイトルバーへ差し込む accessory で、タイトルバーの下にウィンドウ全幅で
  表示される。`contentView` はその下にある。
- タイトルバーのスタイルは1種類だけ（#239 で設定を廃止し、従来の `transparent` に固定した）。
  通常のウィンドウのフルスクリーンも macOS 標準のものだけになった。
- `contentView` は `TerminalViewContainer`（AppKit）で、その中の `NSHostingView` が
  `TerminalView`（SwiftUI）を持つ。左右パネルは `TerminalView` の内側にあるため、
  タブごとに別の View インスタンスになっている。
- 共有範囲は現在こうなっている。

  | 状態 | 単位 |
  | --- | --- |
  | Worktree Status / Agents のモデル（表示状態・内容） | ウィンドウ（#195、親タブから継承） |
  | Markdown プレビューのモデル（表示状態・ファイル・履歴） | タブ |
  | パネルの分割位置（`@State`） | タブ |
  | パネルの View（スクロール位置など） | タブ |

- #239 で削除した `tabs` スタイルの実装（`TitlebarTabsTahoeTerminalWindow.setupTabBar`、
  git の履歴に残っている）は、タブバーの親 View に制約を張り直してタイトルバー内へ移していた。
  タブバーの位置を制約で動かせる前例になる。ただし AppKit の非公開クラス名に依存し、
  タブバーのサイズが変わるたびに張り直す実装だった。

## 検討した案

### A. 状態だけ共有する（不採用）

分割位置などの値を共有モデルへ移す（取り下げた PR #237）。タブバーはパネルの上に全幅の
ままで、構造は変わらない。View はタブごとなのでスクロール位置も揃わない。目標を満たさない。

### B. 標準タブを維持し、パネルの View をウィンドウで1つにする（推奨）

- パネルの状態と View を tabGroup で1つだけ持ち、選択中のタブのウィンドウへ載せ替える。
- タブバーを左右パネルの幅だけ内側へ寄せ、パネルをタブバーの行まで上に伸ばす。
- 標準タブの機能（ドラッグでの切り離し・統合、タブ概要、ウィンドウ復元、タブ色、
  タブ名のインライン編集）はそのまま残る。
- 弱点は AppKit の非公開 View 構造への依存が増えること。成立するかは実機で試さないと
  確定しない（フェーズ0）。

### C. 自前のタブバーにして1ウィンドウ化する（Bが成立しない場合の代替）

- 構造は目標どおりで、非公開 API への依存もなくなる。
- 1タブ = 1ウィンドウ = 1コントローラの前提を崩すため影響が大きい。tabGroup を直接扱う
  コードだけで約135行・12ファイルあり、ウィンドウ復元、フルスクリーン、タブを閉じる確認、
  タブ色、タブ名編集を作り直す。
- タブのドラッグ切り離し・統合など標準タブの機能は自前で再実装しない限り失われる。

## 設計（B）

### 1. 状態の集約

- tabGroup で共有する `WindowPanelState` を新設し、`worktreeStatus`・`agentStatus`・
  分割位置・Markdown プレビューの開閉をまとめる。
- 共有方法は #195 と同じ（`TerminalController.newTab` で親から渡す。新規ウィンドウは新規作成）。
- Markdown プレビューは、開閉だけをウィンドウ単位にする。開閉をタブごとにすると、タブを
  切り替えるたびにタブバーの幅が変わってしまうため。
- プレビューの中身（ファイル・履歴）は従来どおりタブごとに持ち、タブを切り替えると
  そのタブのファイルに切り替わる。スクロール位置もタブごとに保持する。
- プレビューを開いていないタブでは、右パネルに空の状態を表示する。#195 で避けた
  「空パネル」は、枠をウィンドウに固定する以上は残る。
- `zashiki://markdown-preview/open` は従来どおり要求元のタブで開き、ウィンドウのプレビューを
  表示状態にする。

### 2. パネル View の単一化

- `TerminalViewContainer` を「左パネル｜ターミナル｜右パネル」の AppKit レイアウトにする。
- 左右パネルの `NSHostingView` は `WindowPanelState` が1つずつ持ち、タブが選択された
  時点でそのウィンドウのコンテナへ載せ替える。
- 右パネルの View は、選択中のタブの `MarkdownPreviewModel` を表示する。タブごとの
  スクロール位置は View ではなくモデル側に持たせる。
- #195 の既知の制限（Agents のポーリングがタブ数分動く）は解消する。
- `TerminalView` からは `WorktreeStatusSplit` / `MarkdownPreviewSplit` のネストを外す。
- Quick Terminal はタブを持たないので、単独の `WindowPanelState` で同じ経路を通す。

### 3. タブバーをパネルの間に入れる

- パネル表示中は、タブバーの親 View の左右をパネル幅ぶん内側に制約する。パネルの
  表示切り替えと幅のドラッグに追随させる。
- パネルはタブバーの行まで上に伸ばす。ターミナル領域は従来どおりタブバーの下から始める。
- ウィンドウのタイトル行は全幅のまま残す（上の図）。

### 4. 既知のリスク

- タブをドラッグで切り離すと、切り離されたウィンドウにパネルの View が無い状態になり得る。
  tabGroup の構成が変わった時点で、独立した `WindowPanelState` を持たせる処理が要る。
- ネイティブのフルスクリーンではタイトルバーとタブバーが別ウィンドウへ移る。タブバーへの
  制約が効くかは未確認。
- 載せ替えの瞬間に1フレームのちらつきが出る可能性がある。

## 進め方

### フェーズ0: 試作で成立性を確かめる（捨てコード）

次を実機確認し、結果をこの Plan に追記して B / C を確定する。

1. タブバーを左右に内側へ寄せられるか。タブの追加・削除・切り替え・外観変更の後も保てるか。
2. パネルをタブバーの行まで伸ばせるか。
3. タブ切り替え時にパネルの View を載せ替えて、ちらつかないか。
4. ネイティブのフルスクリーンと、タブの切り離し・統合でどうなるか。

1〜3 のどれかが成立しない場合は C を再検討し、Plan を書き直す。

### フェーズ1: 状態の集約

`WindowPanelState` を導入し、Markdown プレビューの開閉と分割位置をウィンドウ単位にする。
View 構造はまだ変えない。

### フェーズ2: パネル View の単一化

コンテナの AppKit レイアウト化と、タブ選択時の載せ替え。

### フェーズ3: タブバーをパネルの間へ

タブバーの制約と、パネルをタブバーの行まで伸ばす処理。

### フェーズ4: エッジケース

タブの切り離し・統合、フルスクリーン、ウィンドウ復元。

フェーズ1〜4はそれぞれ別 PR にし、フェーズ2以降は `needs-verification` を付ける。

## レビューで決めたいこと

- タイトル行をパネルの上に全幅で残してよいか。

決定済み:

- Markdown プレビューは枠と開閉をウィンドウ単位、中身をタブ連動にする。
- タイトルバーのスタイル別の対応は不要になった（#239 で設定を廃止）。

## 検証

- `just lint`、`just test-fast`
- 実機確認（各フェーズの PR ビルド）
  - タブを切り替えても、左右パネルの位置・幅・開閉が変わらない
  - タブを切り替えると、プレビューがそのタブのファイルとスクロール位置に切り替わる
  - プレビューを開いていないタブでは、右パネルが空の状態で表示される
  - タブバーが左右パネルの間に収まり、パネルの表示切り替え・幅の変更に追随する
  - 新規ウィンドウは独立したパネルを持つ
  - Quick Terminal、フルスクリーン、ウィンドウ復元が壊れていない
