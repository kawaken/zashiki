# 左右パネルをウィンドウ直下に置き、タブをその間に入れる

Issue #208

## 目標

「Window → 左右パネル → タブ（タブ内部での分割）」の構造にする。

```
┌────────┬────────────────────────┬─────────────┐
│ ●●●    │ tab1 │ tab2 │ tab3 │ + │ 右          │
│ 左     ├────────────────────────┤ プレビュー  │
│ パネル │ ターミナル（ペイン分割） │             │
└────────┴────────────────────────┴─────────────┘
```

- 左右パネルはウィンドウに1つ。タブを切り替えても位置・幅・開閉が変わらない。
- パネルの中身は選択中のタブに連動する。左は選択中のタブのディレクトリ、右の Markdown
  プレビューは選択中のタブで開いたファイルを表示する。
- タブバーは左右パネルの間だけに表示される。
- タイトル行は持たない。ウィンドウの最上段がタブバーとパネルの見出しになる。

## 方針

macOS 標準のタブをやめ、1つのウィンドウの中に自前のタブバーを持つ。IDE と同じ作りにする。

標準機能を残すことより、構造がシンプルで目標をそのまま表す作りを優先する（レビューで決定）。

## 現状（コードで確認済み）

- タブは macOS 標準のタブ機能。1タブ = 1 `NSWindow` = 1 `TerminalController` で、
  `NSWindowTabGroup` が見た目上1つのウィンドウにまとめている。
- タブバーは AppKit がタイトルバーへ差し込む部品で、ウィンドウ全幅に表示される。置き場所を
  変える正式な方法はない。
- 左右パネルは各タブのウィンドウの中にあるため、タブごとに別の View になっている。
- タブ1枚ぶんの状態は `BaseTerminalController` が直接持っている（ペイン分割のツリー
  `surfaceTree`、フォーカス中のペイン、タイトルの上書き、ベル、Markdown プレビュー）。
  `surfaceTree` の参照は `BaseTerminalController` に60箇所、`TerminalController` に25箇所。
- ウィンドウをまたいでパネルの状態を揃えるために、#195 で「新しいタブへ親のモデルを渡す」
  仕組みと、全タブのペインを集める `tabGroupSurfaces` を入れている。
- 標準タブを直接扱うコードは17ファイル・約155行（`TerminalController` が73行）。
  タブバーの見た目を調整するために AppKit の非公開の View を探す処理も含む。

## 検討した案

### A. 状態だけ共有する（不採用）

分割位置などの値を共有モデルへ移す（取り下げた PR #237）。タブバーはパネルの上に全幅の
ままで、構造は変わらない。

### B. 標準タブのまま、タブバーを裏から動かす（不採用）

試作（`window-scoped-panels-spike` ブランチ）で、タブバーを左右パネルの間に寄せ、パネルを
タブバーの行まで伸ばせることは確認した。ただし次の理由で採らない。

- AppKit の非公開の View 構造に依存し、OS の更新で壊れうる。#239 で削除した `tabs`
  スタイルは同じ手法で、macOS のバージョンごとに別実装が2つ（約1,050行）必要だった。
- タブごとにウィンドウが別なので、パネルを1つに見せるための載せ替え処理が要る。
- タイトルバーの領域に入ったパネルのボタンがクリックできるかは未確認のまま。

### C. 自前のタブバーにして1ウィンドウ化する（採用）

1つのウィンドウが複数のタブを持ち、タブバーは SwiftUI で描く。構造が目標どおりになり、
非公開 API への依存がなくなる。#195 のモデル共有の仕組みも不要になる。

## 設計

### モデル

```
TerminalController（ウィンドウ1つ）
├─ worktreeStatus / agentStatus      … ウィンドウに1つ
├─ パネルの開閉・幅                   … ウィンドウに1つ
├─ tabs: [TerminalTab]
│   └─ TerminalTab（タブ1枚）
│       ├─ surfaceTree（ペイン分割）
│       ├─ focusedSurface
│       ├─ タイトルの上書き、色、ベル
│       └─ markdownPreview（ファイル・履歴・スクロール位置）
└─ selectedTab
```

- `TerminalTab` を新設し、今 `BaseTerminalController` が持っているタブ1枚ぶんの状態を移す。
- コントローラの `surfaceTree` / `focusedSurface` は「選択中のタブ」を指す窓口として残す。
  ペイン分割・フォーカス移動など既存の処理は、選択中のタブに対してそのまま動く。
- ペインから届く通知（プロセス終了、タイトル変更、ベルなど）は、そのペインを持つタブを
  探して処理する。選択中でないタブのペインにも届くため。
- Quick Terminal はタブを1枚だけ持つ形で同じモデルに乗せる。

### 画面

```
HSplit(
  左パネル,
  VStack(タブバー, 選択中のタブのペイン分割),
  右パネル
)
```

- タイトル行はなくす。コンテンツをウィンドウの上端まで広げ、最上段にタブバーと左右パネルの
  見出しを置く。
- タブバーはタブが1枚でも常に表示する。タイトルの表示場所とウィンドウを掴んで動かす場所を
  兼ねるため。ウィンドウのタイトル自体は設定し続ける（Mission Control やウィンドウメニュー用）。
- 信号機ボタンは左上に残る。左上に来る部品（左パネルの見出し、左パネルが閉じているときは
  タブバー）は、ボタンの幅ぶん左を空ける。フルスクリーン中は空けない。
- Markdown プレビューの開閉はウィンドウ単位。中身は選択中のタブの `markdownPreview` を
  表示し、プレビューを開いていないタブでは空の状態を表示する。
- 選択中でないタブのターミナルは描画を止める（今はウィンドウが隠れることで止まっている）。

| 機能 | 扱い |
| --- | --- |

| タブのタイトル、ベルの表示、ショートカット番号の表示 | 作る |
| 新規タブの位置（`window-new-tab-position`）、ディレクトリ・文字サイズの引き継ぎ | 作る |
| タブ・ウィンドウを閉じるときの確認 | 作る |
| ウィンドウ復元 | 作る（保存形式をタブの配列に変える） |
| タブ名の変更、タブの色、右クリックメニュー（他を閉じる・右を閉じる） | 作る |
| 閉じたタブを元に戻す | 作る |

## 進め方

各 PR の時点でアプリが動く状態を保つ。

### PR 1: タブのモデルを切り出す（挙動は変えない）

- `TerminalTab` を新設し、タブ1枚ぶんの状態を移す。コントローラはタブを1枚だけ持つ。
- 標準タブはそのまま。見た目と挙動は変わらない。
- 規模は中。`surfaceTree` を参照する約85箇所の持ち主を整理する。

### PR 2: 1ウィンドウに複数タブ + 自前のタブバー + パネルを外側へ

- コントローラが複数のタブを持ち、標準タブを無効にする。
- 自前のタブバー（選択、閉じる、＋ボタン、タイトル、ベル、ショートカット番号、色の表示）。
- 新規・閉じる・移動・並べ替えのアクションをモデルへつなぐ。閉じるときの確認。
- 画面構成を「左パネル｜タブバー＋ターミナル｜右パネル」にする。パネルのモデルは
  ウィンドウに1つ。Markdown プレビューは開閉をウィンドウ単位、中身をタブ連動にする。
- ウィンドウ復元の保存形式を変える。
- 規模は大。#208 の目標はこの PR で達成する。`needs-verification` を付ける。

この PR の時点では、タブ名の変更は既存のダイアログのみで、右クリックメニュー、閉じたタブを
元に戻す、ドラッグでの並べ替えは一時的に使えない。PR 3 までリリースしない。

### PR 3: タブの機能を戻す

- タブ名のインライン編集、色の変更、右クリックメニュー、閉じたタブを元に戻す、
  ドラッグでの並べ替え。
- 規模は中。

### PR 4: 標準タブ用のコードを削除する

- `TabGroupCloseCoordinator`、タブバーの非公開 View を探す処理、#195 のモデル継承、
  `tabGroupSurfaces`、ウィンドウメニューの標準タブ項目など。
- 規模は中（削除が中心）。

## 最初に確かめること

タブバーとパネルの見出しは、macOS がタイトルバーとして扱う領域に入る。この領域では
クリックが「ウィンドウを掴んで動かす操作」として扱われることがある。PR 2 の最初に、
次が成立するかを確かめる。

- タブや見出しのボタンがクリックできる。
- タブのない余白を掴んでウィンドウを動かせる。余白のダブルクリックで拡大・縮小できる。
- タブのドラッグ（並べ替え）がウィンドウの移動と取り違えられない。

成立しない場合は、最上段に掴むためだけの細い帯を残す形に切り替える。

## 既知の影響

- 更新前に保存されたウィンドウ復元データは、タブがそれぞれ別のウィンドウとして復元される
  （タブのまとまりは旧形式から復元できない）。更新後の1回だけ。
- タブをドラッグして別ウィンドウに切り離す操作はできなくなる。必要になれば
  「タブを新しいウィンドウへ移す」メニューとして後から足す。

## レビューで決めたいこと

- タブをドラッグして別ウィンドウに切り離す・移す機能を、初期の範囲から外してよいか。

決定済み:

- 標準タブをやめ、自前のタブバーにする。
- タイトル行はなくし、タブバーを常に表示する。
- Markdown プレビューは枠と開閉をウィンドウ単位、中身をタブ連動にする。
- タイトルバーのスタイル別の対応は不要（#239 で設定を廃止）。

## 検証

- `just lint`、`just test-fast`、`just test`
- 実機確認（PR 2 以降）
  - タブを切り替えても、左右パネルの位置・幅・開閉が変わらない
  - タブを切り替えると、プレビューがそのタブのファイルとスクロール位置に切り替わる
  - タブバーが左右パネルの間に表示され、クリック・キーバインドで操作できる
  - 選択中でないタブでもプロセスが動き続け、終了・ベル・タイトル変更が反映される
  - ウィンドウ復元、フルスクリーン、Quick Terminal が壊れていない
