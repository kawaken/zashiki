# Markdownプレビューのヘッダーと右クリックメニューの整理

## 対象

- Issue #278
- 外部アプリ設定の統合は #276 の担当範囲。この変更ではプレビューパネル内の設定への入口だけを外す。

## 合意済みの表示

ヘッダーを次の順序にする。

```text
[戻る・進む・履歴]  ファイル名          [外部アプリで開く] […] [閉じる]
```

- 「4つ」はボタンの4系統（履歴系・外部アプリ・…・閉じる）と解釈する。戻る・進む・履歴一覧の3ボタンは維持する。
- ファイル名はメニューではなく通常のテキストにし、下向き矢印を外す。1行・中央省略・フルパスのツールチップは維持する。
- 外部アプリボタンは設定済みの既定アプリを1クリックで開く。
- 独立したFinder・フォントサイズボタンは「…」へ移す。
- 「…」と右クリックには以下の共通項目を同じ順序で出す。

| グループ | 項目 |
| --- | --- |
| コピー | Markdown原文をコピー／絶対パスをコピー／相対パスをコピー |
| 開く | アプリを選んで開く（サブメニュー）／Finderで表示 |
| 文字サイズ | フォントサイズ変更… |

グループ間には区切り線を入れる。原文コピーはFront Matterを含むファイル全体のコピーとして残す。選択した表示テキストのコピーとは区別する。

## 調査結果

- `MarkdownPreviewPane` のファイル名メニューがコピー・Open With・外部アプリ設定への入口を持ち、外部アプリボタンの右クリックにも外部アプリ設定への入口がある。
- コピー・Finder・外部アプリを開く処理はすでに同View内にあり、そのまま再利用できる。
- フォントサイズは既存のpopoverでスライダーと `Match Terminal` を提供する。保存値とサイズ計算方針を変える必要はない。
- 本文はセクションごとの `StructuredText` で描画し、Textualのテキスト選択を有効にしている。Front Matterは別のSwiftUI Viewで描画している。
- 固定依存のTextual 0.5.0（`01b51875a5406eefc95f52a058cb059e7bc94dc4`）のソースを確認した。`NSTextInteractionView` は `rightMouseDown(with:)` と `menu(for:)` で選択範囲を調整し、Copy・ShareのAppKitメニューを生成する。
- Textualの公開APIには、そのAppKitメニューへ項目を追加する入口が見当たらない。親ViewへSwiftUIの `.contextMenu` を付けるだけで、本文の既存メニューに項目が追加されるとは扱わない。
- 現在の `Cmd+C` は非ターミナルのfirst responderへCopyを転送する。今回その経路や新しいショートカットは変更しない。

## 実装方針

### ヘッダーと共通操作

1. `fileMenu` をファイル名表示と「…」メニューへ分ける。
2. メニュー項目の識別子・表示名・グループ・利用可否・実行処理を共通化する。「…」用と右クリック用で順序や判定を個別管理しない。
3. 外部アプリの一覧と既定アプリのチェック表示を再利用する。パネル内の `Configure External Apps…` はすべて取り除く。
4. 既定アプリボタンの既存の専用右クリックメニューも共通メニューへ揃える。
5. フォントサイズpopoverは「…」を表示位置の基準にし、共通項目から開く。本文の右クリックからでも同じUIと保存値を使う。

### 右クリックと既存のテキスト操作

- 対象は現在表示されているプレビューパネル内（ヘッダー・本文・余白・空状態・エラー状態）。履歴や文字サイズのpopover内部は対象に含めない。
- 本文の既存Copy・Shareを維持し、その後に区切り線と共通項目を追加する。本文選択がない場所では共通項目だけを出す。
- 最初に、パネル内に限定したAppKitのイベント橋渡しを試作する。右クリックの位置から対象Viewを特定し、公開の `menu(for:)` で既存メニューを取得したうえで共通項目を追加して表示する方法を検証する。
- Textualの非公開型名・内部プロパティ・メソッド差し替えには依存せず、依存ライブラリの更新やforkは行わない。
- イベントを監視する場合はwindowとパネルの表示領域で絞り、通常クリック・テキスト選択・リンク・スクロール・ターミナルには介入しない。Control-clickにも同じ処理を適用する。非表示化・タブ切替・破棄時の監視解除を扱う。
- 共通操作が新しいSwiftファイルを必要とする場合は、既存のXcodeプロジェクトのソース登録方法に従う。
- 既存メニューとの共存が実機で成立しない場合は、調査結果と代替案をこのPlanに追記してから方式を変更する。選択コピーを消して完成扱いにはしない。

### 操作の利用可否

| 状態 | 動作 |
| --- | --- |
| ファイル未選択 | 原文・パス・外部アプリ・Finderを無効化。文字サイズ変更は利用可能 |
| 読み込みエラー | 原文コピーを無効化。URLがあればパス・外部アプリ・Finderは利用可能 |
| 空のMarkdownファイル | 空文字列として原文コピー可能 |
| 相対パスの基準なし | 相対パスコピーだけ無効化 |
| 外部アプリ未設定 | 外部アプリボタンとOpen Withを無効化。Finderやコピーは利用可能 |
| 既定アプリなし・候補あり | ワンクリックの外部アプリボタンは無効化。Open Withで候補を選択可能 |

相対パスの基準はファイルを開いた時点のディレクトリを維持する。外部アプリ起動失敗時の既存アラートも維持する。

## 検証

- 共通項目の順序・利用可否・アクション対応と、右クリックで既存メニューを残す処理に必要なテストを追加する。UIの見た目を写すだけのテストは追加しない。
- 既存のMarkdownプレビューモデル・相対パス・原文コピー・文字サイズ関連テストを確認し、変更範囲に応じて実行する。
- SwiftLint、Swiftコンパイル、`just test-fast` を実行する。実行できない検証は理由と範囲を記録する。
- 実機では狭いパネル・長いファイル名・履歴移動後の対象ファイルを確認する。
- 本文の選択あり・なし、右クリックによる単語選択、Front Matter、リンク、コードブロック、表、画像、余白でメニューを確認する。既存のコピー・共有と `Cmd+C` が継続して動くことも確認する。
- 複数ウィンドウ・タブ切替・パネル開閉後に他のターミナルやメニューへ影響がないことを確認する。
- 「…」・右クリックの両方からコピー、外部アプリ、Finder、文字サイズ変更を試す。コピー内容・外部アプリ候補と既定値の変更・サイズ保存・ターミナル追従を確認する。
- 実装PRには `needs-verification` を付け、アプリ成果物で実機確認する。ラベルがある間はAutoMergeを有効にしない。

## 進め方

- まずIssueを作成・claimし、調査とこのPlanをdraft PRへ出す。
- Planレビュー後、同じPRで実装・検証し、結果を追記して `docs/history/` へ移す。
- 実装完了後にPRをreadyにする。実機確認が済み `needs-verification` が外れたら通常のAutoMergeへ進む。
- 必要なPRがすべてマージされた後、Issueに結果を記録して `wip` を外し、Issueを明示的に完了する。

## 対象外

- 設定画面の統合や設定データの移行
- 履歴UI・ナビゲーション・履歴保存の仕様変更
- コピー用の新しいショートカット
- Markdown描画・セクション分割・文字サイズ仕様の変更
- 原文コピーや相対パス計算のモデルAPIの削除
