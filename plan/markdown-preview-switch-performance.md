# Markdownプレビューの履歴切り替え高速化

## 対象

- Issue #222

## 調査結果

`MarkdownPreviewModel.show(url:)` は、表示対象を設定したあとに `reload()` を呼び出している。一方、`MarkdownPreviewFileWatcher` の初期化時にファイル監視を開始すると、監視のarm完了時にも `onChange` を呼び出しているため、同じファイルを開く操作で内容の読み込みが二重に発生する。

履歴の戻る・進むや履歴一覧からの移動は毎回 `show(url:)` を通るため、ファイル読み込みだけでなくMarkdownの再描画も重複し、切り替え待ちを増やしている可能性がある。

## 方針

- ファイル表示時の初回読み込みを、ファイル監視の初期コールバックに一本化する。
- ファイルが初期化時点で読み込めない場合も初期コールバックを実行し、既存のエラー表示を維持する。
- ファイル変更時や監視の再arm時の自動リロード挙動は維持する。
- 履歴モデルの戻る・進む・一覧選択の意味は変更しない。

## 実装内容

- `MarkdownPreviewModel.show(url:)` の重複した明示的 `reload()` を削除する。
- `MarkdownPreviewFileWatcher` が初回の監視開始に失敗した場合も初期変更通知を行う。
- 初回表示、履歴移動、ファイル変更、ファイル削除後の再取得をテストまたは既存テストで確認する。

## テスト・検証

- `MarkdownPreviewModelTests` の既存履歴テストが通過する。
- `just lint` とCIの `just test-fast` を実行する。
- 実機確認はリリース後に行うため、CI通過後にマージする。

## 対象外

- Markdown本文のキャッシュや履歴の永続化
- Markdownレンダリングエンジンの置き換え
- 履歴UIの変更（#221）
