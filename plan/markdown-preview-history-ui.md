# Markdownプレビューの表示履歴UI

## 対象

- Issue #221
- 既存の戻る・進む履歴ナビゲーション（Issue #210 / PR #215）を拡張し、開いたMarkdownファイルを一覧から選択できるようにする。

## 背景

`MarkdownPreviewModel` には、現在表示中のファイル、戻る・進む用の履歴配列、現在位置がすでに存在する。一方、`MarkdownPreviewPane` のヘッダーから利用できるのは戻る・進むボタンだけで、履歴全体を確認したり、離れた履歴項目へ直接移動したりできない。

## 方針

- 既存の履歴配列を単一の情報源として利用し、別の履歴管理を作らない。
- `MarkdownPreviewModel` から履歴項目と現在位置をSwiftUIが読み取れるようにする。
- 履歴項目には表示名に加えてファイルURLを保持し、同名ファイルでも識別できるようにする。
- ヘッダーに履歴UIの入口を追加する。
- 履歴UIでは開いた順にファイルを一覧表示し、現在のファイルを選択状態で示す。
- 履歴項目を選択した場合は、戻る・進むと同じく既存履歴内を移動し、新しい履歴項目を追加しない。
- 新しいファイルを開いた場合は、既存のブラウザ風挙動どおり、現在位置より先の進む履歴を破棄する。
- 履歴UIの表示は現在のMarkdownプレビューモデルの寿命に限定し、アプリ再起動後まで永続化しない。

## 実装内容

- `MarkdownPreviewModel` の履歴情報をSwiftUI向けの読み取り可能な形へ整理する。
- 任意の履歴項目へ移動するメソッドと、履歴選択後のナビゲーション状態更新を追加する。
- `MarkdownPreviewPane` のヘッダーに履歴一覧を開く操作を追加する。
- 履歴項目の表示名、パス、現在位置を確認できる一覧UIを実装する。
- 既存の戻る・進むボタンと履歴一覧選択が同じ履歴状態を共有することをテストする。

## テスト・検証

- 単一ファイルでは履歴UIが空または無効状態になる。
- 複数ファイルを開くと全項目が開いた順に表示される。
- 履歴一覧から過去の項目を選ぶと、そのファイルへ移動し、現在位置が更新される。
- 履歴一覧から移動した後に新しいファイルを開くと、進む履歴が破棄される。
- 同名ファイルでもURLが異なる項目を区別できる。
- 既存のMarkdownPreviewModelTests、SwiftLint、CIを実行する。
- 実機確認はリリース後に行うため、CI通過後にマージする。

## 対象外

- 履歴のディスク永続化
- 複数ウィンドウ・タブ間での履歴共有
- #224の「指定アプリで開く」導線
- Markdown本文内リンクの遷移（#223）
- 履歴切り替えの性能改善（#222）
