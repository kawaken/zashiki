# 設定ダイアログとGUI優先の設定管理

## 対象と現在の段階

- Issue #276、方針レビュー用PR #277。
- 今回は設計のみ。アプリや利用者の設定は変更しない。
- 構文を調べ直さず、必要な設定をダイアログから変更できるようにする。
- 利用者とのレビューにより、GUIで保存した項目を手書き設定より優先する方式を採用する。共有は「Show as Text」で設定形式のテキストを表示・コピーできればよく、ファイルへのエクスポートは初回の要件にしない。

## 採用する方針

1. アプリの既定値を基礎にする。
2. 既存の設定ファイルと参照先を、これまでの読み込み規則で適用する。
3. GUIで明示的に変更・保存した項目を上書きする。

GUIで触っていない項目は設定ファイルやテーマから引き継ぐ。SaveはGUI用の保存先だけ更新し、主設定ファイル、参照先、同梱テーマは書き換えない。コメント・分割構造・シンボリックリンクは読み取りだけで維持される。

設定ファイルの値がGUIで上書きされることを画面で確認できるようにし、項目ごとにGUIの指定を解除してファイルの値へ戻せるようにする。

起動時のCLI引数は永続化しない。明示的なCLI指定があるキーはGUIの上書き対象から除き、そのキーは既存のCLI・ファイル読込経路の結果を維持する。通常起動での「設定ファイルよりGUI優先」と、起動時だけの明示指定を区別する。

## 調査結果と再利用

- `src/config/Config.zig`に公開設定169項目がある。以前の170項目には内部用のキーが含まれていた。
- `src/config/key.zig`からキーと値の型を列挙できる。単純型やenumの入力画面は共通部品から組み立てられる。
- `src/helpgen.zig`と`src/build/HelpStrings.zig`が設定・キーバインドアクションの説明を生成している。
- `src/config/formatter.zig`で個別値を設定形式へ出力できる。GUI用の保存とShow as Textに共用する。
- `src/config/formatter_file.zig`と`+show-config`は実効設定を出力できるが、テーマ由来の色や実行時補完値を固定化するため、GUIの保存内容を作る用途にはそのまま使わない。
- 現在の読み込み順序は既定値、標準ファイル群、CLI、参照先、finalize。GUIの適用は参照先読込後、finalize前に組み込む。ファイル末尾のincludeで優先度を実現しようとしない。
- テーマはfinalizeで読み込み、設定を再適用する仕組みになっている。GUIの指定も再生対象に含め、light/darkの切替後も優先順位を保つ。
- フォント一覧などの繰り返し型は、後から読み込むだけでは追加になる。GUIでの置換、項目単位の上書き、明示的な空値を区別する必要がある。
- `finalize`で数値を丸める項目があるため、診断だけでなく採用される値も確認する。
- `SettingsView.swift`は未使用の案内画面。「Settings…」は現在外部エディターを開く。
- Markdown外部アプリはUserDefaultsに保存され、専用画面から即時反映されている。共通のSave/Cancelへ移す。

## GUI対応の範囲

- 初回から169項目すべてをGUI化しない。現在使っている設定と、今後変更したい設定を利用者が選び、それを優先する。
- 既定値のままで使っていて変更予定のない項目は後回しにする。「既定値と一致するか」だけで編集可否を自動判定する方式にはしない。
- 初回の具体的な項目は利用者と選定する。外部アプリ設定は今回の統合対象として維持する。
- 保存時はGUI未対応の項目も元のまま残す。

用途別の整理は次のとおり。数は現在の設定キー数であり、GUIの画面数や入力欄数ではない。外部アプリの新しい設定キーはまだこの数に含まれない。

## ダイアログ

- 左側にカテゴリ、上部に検索、右側に型に合った入力部品を置く。カテゴリは対応する項目に合わせて絞る。
- スイッチ、数値・単位、選択肢、色、フォント、パスなどを共通部品にする。説明と設定キーで検索できるようにする。
- 行には実効値を表示し、GUI指定がある項目は「GUIで上書き中」と分かるようにする。必要なときにファイル側の値も確認できる。
- 「設定ファイルの値に戻す」はGUIの指定だけ解除する。ファイルに指定がなければテーマやアプリの既定値へ戻る。
- 値がたまたま既定値と一致していても、利用者が明示的に保存した指定は維持する。GUI未指定と明示指定を混同しない。
- 「GUIで変更した項目のみ」の表示を用意する。
- 編集はSaveまで作業中の値に保持し、Cancelで破棄する。未保存変更を残して閉じる際は保存・破棄・継続を選べる。
- 保存後は既存の再読み込みを使う。新しいターミナルや再起動が必要な設定はその旨を表示し、勝手に再起動しない。
- 「設定ファイルを開く」を残す。直接ファイルを開く既存のCLIやキーバインドアクションは維持する。
- アプリの「Markdown External Apps…」独立メニューはなくす。プレビューの設定導線は同じダイアログのMarkdownカテゴリを開く。

## Show as Text

- ダイアログに「Show as Text」を用意し、GUIで指定した設定だけを従来の設定ファイル形式で表示する。
- 編集中の場合は未保存の変更を含むことを示す。表示やCopyを押しただけではSaveしない。
- 選択・コピーできる読み取り専用の表示とCopyボタンを用意する。初回は保存先を選ぶエクスポート機能やテキストからのインポートを作らない。
- アプリの全既定値、テーマ由来の全パレット、CLIからの一時指定、実行時の補完値は含めない。
- GUI指定がなければ空であることを説明する。手書き設定ファイルのコピーや統合はこの表示の役割にしない。
- 表示したテキストは通常の設定パーサーで読め、GUI指定と同じ意味になるようにする。

## 設定基盤と保存

### GUIが管理する保存先

- Application Support内にGUI管理専用の`gui-settings.ghostty`を設ける。通常の設定と同じ構文を使い、GUIで明示的に指定した値だけを保存する。
- このファイルは既存の標準設定ファイルとは別に、GUIの上書きとして明示的に読み込む。既存ファイルに`config-file`を書き足さない。
- Zig側のCLIとSwift側のアプリで同じ読込関数を使い、再読み込みや`+show-config`でも同じ実効値にする。`+show-config --default`はGUIを含まないアプリの既定値のままにする。
- GUI未指定、空文字、false、ゼロ、空一覧、継承へ戻す状態を区別する。
- GUIの保存内容は指定したキーだけから作る。実効設定全体を逆算して保存しない。
- `config-file`や`config-default-files`など読み込み構成を変える項目はGUI管理の対象にせず、引き続き設定ファイル・起動引数で扱う。
- GUI管理ファイルに将来版の未対応キーがある場合は、Saveで黙って消さない。編集を止めて理由を表示し、元の内容を保持する。

### 上書きの単位

- 単一値はGUIの明示指定で置き換える。
- フォントなどの一覧はGUIでその一覧を編集した場合に一覧全体を置き換える。リセットの指定を含め、ファイル側への意図しない追加を防ぐ。
- キーバインドは編集したトリガー単位、パレットは編集した番号単位で上書きする。触っていない既存設定は残す。GUIの指定解除と、既存のバインドを無効にする操作は別に扱う。
- フラグ集合などは編集単位と既存パーサーの意味を対応させる。必要な型だけアダプターを作り、追加・置換・削除を往復テストで検証する。
- light/darkテーマを維持し、選択したテーマの実効色すべてをGUI指定として保存しない。

### 検証と反映

- ファイルから読み込んだ設定にメモリー上のGUI候補を適用し、既存パーサーとfinalizeで検証する。既存ファイルやGUI保存先を先に書き換えて検証しない。
- 再読み込みと検証はGUIの適用・CLI指定の扱い・テーマ再生を含めて共通化する。
- GUIで選ぶファイルやディレクトリは保存時に絶対パスへ正規化する。手書きファイル内の相対パスの基準は変更しない。
- 入力エラー、丸められる数値、項目間の影響を表示する。不正な候補は保存しない。
- GUI保存先の外部変更を検出した場合は、保存済みの内容を上書きせず再読み込みを促す。手書きファイルが変わった場合は基礎となる値を再取得する。
- GUI保存先は同じディレクトリの一時ファイルからatomic replaceし、失敗時は前の保存内容と編集中の値を保持する。
- 保存成功後に再読み込みする。保存成功と反映失敗は区別して伝える。
- 既存設定ファイルのコメント、改行形式、重複行、参照先、シンボリックリンクを再構成する処理は不要になる。

## 設定定義とGUIの接続

- Zig側でキー、説明、型、選択肢、既定値、ファイル側の値、GUI指定、実効値を構造化し、C API経由でSwiftへ渡す。
- 通常のGUI操作でCLIプロセスを起動して出力を解析する方式にはしない。
- 単純型・enumは共通フォームへ対応させる。カテゴリ、表示名、単位、適用タイミングなど型から分からないUI情報だけ追加する。
- GUI対象キーと編集部品の対応を機械的に検査する。全公開キーへ編集UIを作ることは完了条件にしない。
- キーバインドなどの高度な編集は必要な範囲から追加する。
- C APIはスキーマ、GUI候補の検証、上書きの適用、個別値のシリアライズを担当し、設定の意味をSwiftに複製しない。

## 外部アプリ設定の統合

- 名前、安定したID、URLテンプレートを持つアプリ一覧と既定IDを設定定義へ追加し、Show as Textでも出力できるようにする。
- 任意のURLの予約文字や引用符を壊さない可逆なレコード構文を、パーサーとformatterの往復テストで確定する。
- GUIに明示指定があればファイルより優先する。未指定と明示的な空一覧を区別する。
- 旧UserDefaultsの保存がある場合はGUI設定の移行候補として読む。初回SaveでGUI管理ファイルへ保存し、画面を開くだけでは書き込まない。
- Save成功後に移行完了を記録し、Cancelや失敗時は旧データを保持する。移行後にGUI指定を解除しても旧登録が復活しないようにする。
- 既存のURL検証・生成・起動処理を再利用し、編集時の即時保存は共通のSave/Cancelへ揃える。
- ウィンドウ状態などの一時的なUI状態はUserDefaultsに残せる。OSの権限許可は今回の保存対象にしない。

## 代替案と判断

- **設定ファイル優先**: ファイルへ記述済みの項目をGUIで変更しても反映されないため、採用しない。
- **手書き設定ファイルをGUIから差分更新**: 保存元の選択、コメント・参照先・シンボリックリンクの扱いが必要になるため、GUI管理の保存先へ切り替える。
- **実効設定を全保存・全文表示**: テーマの色や実行時の補完値を固定化するため採用しない。GUIで指定した内容だけを扱う。
- **全設定の専用UIを一度に作る**: 共通フォームで扱いやすい設定を広く載せ、高度な設定は必要に応じて追加する。
- **エクスポート用の保存ダイアログ**: Show as TextとCopyで足りるという利用者の希望に合わせ、初回の対象外とする。

## 実装順序

1. **設定基盤**: GUI管理の保存、既存ファイルからの継承、GUI優先の適用、解除、検証、テキスト生成。
2. **設定ダイアログ**: Settingsの入口、カテゴリ・検索、共通フォーム、Save/Cancel、上書き元の表示、Show as TextとCopy。
3. **必要な複合型**: リスト・フラグ・キーバインドなどを必要な範囲から追加する。
4. **外部アプリ統合**: 保存内容の移行、専用メニューの整理、プレビューからMarkdownカテゴリを開く導線。
5. **実機確認**: 保存・解除・再起動・手書き設定との共存・Show as Textの往復を確認する。

実装を複数PRへ分ける場合もIssue #276を継続し、最後の必要なPRがマージされるまで`wip`を維持する。今回のdraft PRは設計レビュー用のままにする。

## 検証計画

- ファイルのみ、GUIのみ、同じ項目の競合、GUI解除後のフォールバック、明示的なfalse・ゼロ・空値。
- Saveしなければ変更しないこと、Save失敗時の保持、外部変更、再起動後の永続化。
- 分割ファイル、相対パス、シンボリックリンクを含む手書き設定がSave前後で不変であること。
- テーマ切替・再読み込みでもGUI指定が優先され、未指定の色はテーマに追従すること。
- フォント一覧の置換、キーバインドの部分上書き・無効化・解除など、採用した複合型の合成規則。
- CLI指定の非永続化と、GUI指定と衝突する場合の既存経路の維持。`--config-default-files=false`とGUI保存の共存も確認する。
- Show as TextがGUI指定だけを含み、再パースした意味が一致すること。表示・Copyで保存しないこと。
- 外部アプリの移行・Cancel・失敗・空一覧・移行後の解除。
- 関連Zig/Swiftテスト、`just lint`、`just test-fast`。画面・操作は`needs-verification`のPR成果物で確認する。
